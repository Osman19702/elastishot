The problem

Pixel diffs answer the wrong question

They ask "is this pixel the same?" A tester asks "what changed?". Three everyday situations break the first question completely.

A banner appears at the top

Every pixel below it moves down. A pixel diff marks the entire page; the one real change is buried.

Elastishot matches the strips of the page in sequence, reports one added region and compares the rest in place.

A section collapses

Content below jumps up by its height. The diff says everything after the FAQ changed.

Elastishot reports the removed rows once and keeps the footer matched.

The capture is zoomed or cropped

A 320 px crop and a 1080 px full page share no pixel grid. Same-size comparisons refuse or resize blindly.

Elastishot recovers the scale and offset from features, then compares only what both captures show.

What you get

Everything a review needs, from capture to verdict

Feature alignment

ORB keypoints and RANSAC recover zoom, crop and whole-pixel shifts; same-size captures are snapped to an exact shift so nothing is resampled.

Structural alignment

Same-size captures are aligned row by row from row hashes, and side-by-side columns that move on their own get their own lanes, so inserted banners, collapsed sections and a column that grew are one region each.

Four kinds of region

Added, removed, changed and moved, each with a score, a box on both sides and the pixels behind it. Moves are found by template matching.

Named elements

Playwright captures record an element map; every region is attributed to the smallest element covering it: test id first, then id, role and name, then a CSS path.

A viewer people actually use

Slider, flip, blink, overlay and diff, as one web component you can drop into your own tool. It is what you are using above.

Reports for people and for CI

A summary page, a page per pair, JSON with the full result, JUnit XML, exit codes 0, 1 and 2. Warnings from the engine reach the page.

A CLI built for baselines

run captures every target and viewport in a config, compares against approved baselines, and approve promotes a run. Files in your repo, nothing else.

Honest when unsure

Error pages, low feature spread, fallbacks and partial coverage are warnings on the pair, never silent. A capture that answered 404 says so.

Small changes

One digit, one price, one word

Release checks fail on the small things: a version badge, a price, a renamed button. Same-size pages are compared pixel for pixel, so a single changed character is a region with a name, not noise that a tolerance swallowed.

How it works

Five stages, every one of them reported

Capture

Playwright opens the URL, freezes animations, hides what you tell it to, screenshots the full page and records an element map.

Global alignment

Features on both captures vote for a scale and offset; the candidate is warped onto the baseline's pixel grid, exactly when the pages share a size.

Structural alignment

Horizontal strips are matched in sequence; runs that only exist on one side become inserted or deleted bands.

Diff and classify

Matched bands are diffed in perceptual colour space, components are merged into regions and moved blocks are recognised.

Name and report

Regions meet the element maps; the pair page, the summary, JSON and JUnit are written; the exit code tells CI.

Get started

Two captures in, a verdict out

Compare two URLs or two images

npm install -D elastishot playwright
npx playwright install chromium

npx elastishot compare https://staging.example.com/ \
                       https://example.com/ --full-page
# exit 1: differences, report in .elastishot/runs/<run>/index.html

Track targets across deployments

// elastishot.config.js
export default {
  viewports: [{ name: 'desktop', width: 1280, height: 800 },
              { name: 'mobile', width: 390, height: 844 }],
  capture: { fullPage: true },
  targets: [{ name: 'home', url: 'https://example.com/' },
            { name: 'pricing', url: 'https://example.com/pricing' }],
}
// npx elastishot run --update   # approve the current state
// npx elastishot run --junit    # every deploy after that

Embed the viewer

import 'elastishot/viewer'

<elastishot-viewer baseline-src="a.png" candidate-src="b.png"
                   diff-src="diff.png" mode="slider" show-regions>
</elastishot-viewer>
// viewer.regions = result.regions; viewer.locators = result.locators

Use the engine from Node

import { comparePair } from 'elastishot'
import { capture } from 'elastishot/capture'

const before = await capture('https://example.com/', { fullPage: true })
const after  = await capture('https://staging.example.com/', { fullPage: true })
const { pass, result, locators } = await comparePair(before, after)
console.log(pass, result.summary.similarity, locators.changedLocators[0])
Roadmap

Where it goes from here

Dates are targets; the order is the commitment. The full document lives in the repository as docs/ROADMAP.md.

  • September 2026 · done

    0.1 Foundation

    • Feature and structural alignment, four region kinds, move detection
    • Element maps and named regions, viewer, reports, JUnit, CLI with baselines
    • 195 tests, a 13-pair field test, the Lumen lab with ground truth
    • Published on npm with provenance; exact row and lane alignment took the lab's false positives from 19 to 1
  • October 2026

    0.2 Trust

    • Column-axis structural alignment for sidebars and reordered columns
    • Moves named on both ends; resized elements in the changed-elements table
    • Ignore by selector; flaky-region memory across runs
    • GitHub Action; worker threads and a SIMD build for speed
  • November to December 2026

    0.3 Teams

    • Approve from the report page; run history against the previous run
    • Component mode for Storybook and URL lists; Firefox and WebKit captures
    • Reporters as plugins: pull-request comment, Slack, S3
  • First quarter 2027

    1.0 Stable

    • Report and element-map schemas frozen; plugin API with a deprecation policy
    • Published benchmark against pixelmatch and BackstopJS on the lab and the field set
    • Documentation site, report accessibility
  • 2027

    Hosted, as an opt-in reporter

    • Baselines per branch, history, shareable links, GitHub App checks, browser approval
    • The open core stays complete; the CLI never contacts the service unless configured
